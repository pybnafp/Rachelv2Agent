# Rachel Experience

## 定位与边界
这不是 `SKILL.md` 的替代品，也不是 `refs.md` 的技术说明。

这里存放路线规划过程中反复验证出来的经验性先验、常见误判模式和实战偏好，用来帮助 LLM 在多个“看起来都能走”的方案里做更像化学家的排序与取舍。它们始终只是可被当前底物事实、机理证据和更优路线推翻的参考。

Rachel 的共同工作哲学是：

- Rachel 提供化学事实、候选空间、风险和审计信息，LLM/化学家负责判断与设计。
- 化学真实合理和整条路线质量永远优先于模板、反应名、分数和局部方便。
- 可以大胆提出未列出的反应和 de novo 路线，但每一步必须严格验证、严格审计。
- gate 的价值是提醒补证据、修前体和重新思考，而不是代替 LLM 拒绝化学方案。
- 经验卡负责提醒当前最值得检查的问题，不负责给出反应结论。

使用优先级：
- `SKILL.md` 的硬规则优先
- 化学机理与合成事实优先
- 本文档的经验先验用于排序、怀疑和校正
- 模板命中、CS、confidence 只作参考

使用原则：
- 经验先验不是机械规则，不能压过明确的底物事实和文献逻辑
- 若经验与当前底物不匹配，应主动弃用，而不是硬套
- 新增经验时优先写“适用范围”和“失效边界”

## 核心经验先验

### 先验 1. 先数骨架原子，再谈反应类别
- 逆合成里最贵的错误通常不是“反应类型选错”，而是环大小、并环方式、桥连关系、骨架原子数先看错。
- 一旦骨架识别错，后面的模板、评分、手柄规划都会跟着错。
- 高稠合、刚性、富芳香的杂环骨架优先保骨架，先拆外接手柄，不为降 `CS` 强行开环。
- 用户如果指出“五元环还是六元环”“这里是不是少了一个碳”“并环方式不对”，应优先停下来重算拓扑，不要继续往下拆。
- 凡是产物相对核心前体新增了 C/N/S 等骨架原子，必须逐一说明来源；如果模板没有把来源显式写出，就用完整 `precursors/reagents` 登记 `propose_action`，再走 `try_action`。

### 先验 2. 成熟药化杂环优先保骨架，优先做后期编辑
- `benzofuran`、`indole`、`quinoline`、`benzimidazole`、稠合 `aza-oxa` 等成熟药化骨架，默认优先保留。
- 对这类骨架，优先考虑后期卤化、偶联、氧化、酰化、N-官能化等编辑，而不是轻易回到开环或前环合前体。
- 对成熟杂环若 Rachel 给出的深拆主要是环内 `Williamson`、`Chan-Lam`、`Paal-Knorr` 或奇怪重排，默认先高度怀疑。
- 越是刚性、稠合、富芳香的骨架，越不应为了降 `CS` 强行开裂。

### 先验 3. 顶层优先天然收敛；复杂片段 `sp2-sp2` 连接优先考虑 `Suzuki`
- 如果目标本身就带有 `amide`、`urea`、`sulfonamide`、`carbamate` 等天然汇聚位点，优先把它们当作后期收敛连接点。
- 两个复杂片段若只通过一个 `sp2-sp2` 键连接，且没有更自然的汇聚方式，顶层优先考虑 `Suzuki` 收敛断键。
- 不要为了“拆得更深”而放弃明显更自然的收敛设计。

### 先验 4. 芳基-烯基连接常优先考虑 `Heck`，但必须看底物语境
- 芳基-烯基连接优先考虑 `Heck`，尤其当烯基来自现成小环烯烃时。
- 这是一条经验性偏好，不是硬规则；若底物更像交叉偶联、烯基卤/硼酸酯更现成，仍应让位于更自然方案。
- `Heck` 更适合明确的芳基-烯基连结，不应机械替代 `Suzuki` 或其他更匹配的偶联。

### 先验 5. 必须区分永久手柄和临时手柄
- 必须区分永久手柄和临时手柄；最终收敛偶联手柄优先保留，临时手柄可以后期再装。
- 活化杂芳环上的局部卤化通常更像后期步骤，而不是前期预埋。
- `benzyl bromide`、`acid chloride`、`free tetrazole`、`organotin`、高活性烯基卤/烯基锡等，默认晚装。
- 如果某个把手不是最终收敛手柄，就尽量不要带着它跑很多步。

### 先验 6. 每一步都要追关键碳来源，碳账比模板更重要
- 每一步都要追关键碳来源，尤其是 `N-methyl`、`mesyl methyl`、`amide carbonyl`、苄位氧化后的羧酸碳。
- `mesylation` 会新增一个甲基碳，这个碳必须明确来自 `MsCl`。
- `amide` 的羰基碳来自酸/酸氯一侧，不来自胺。
- `CH3 -> CO2H` 往往是同一个碳被氧化升级，不是新增一个羰基碳。
- 若一条路线说不清关键碳、卤素或保护基来源，即使模板执行成功或 `validation.decision_gate.state=clear` 也不应轻易提交。

### 先验 7. `2-methyl heteroaryl -> 2-carboxy heteroaryl` 常优先回溯为苄位氧化
- `2-methyl heteroaryl -> 2-carboxy heteroaryl` 常优先通过苄位氧化回溯，而不是反向硬造酸。
- 看到杂芳环邻位羧酸时，要优先问自己：它是不是从同位甲基氧化上来的。
- 这类回溯通常比“凭空组装一个更复杂的酸片段”更自然，也更贴近药化路线。

### 先验 8. 多组分与一锅法最容易漏写组分
- 还原胺化、`Mannich`、`Strecker`、`Ugi`、`Passerini`、缩合成环等，最容易出现“主前体写了，小分子没写全”的问题。
- 一旦漏写关键小分子，系统常会报 `skeleton_imbalance`，但真正的问题往往不是骨架错，而是清单不完整。
- 经验上，凡是“看起来一步就能把很多原子接上去”的方案，都要先做组分完整性审计。

### 先验 9. 保护不是注释，是实际路线节点
- 保护/脱保护如果真有必要，就必须当成真实步骤写入树。
- 自由芳胺常干扰卤化、Pd 偶联和强氧化，关键建键前保持保护态通常更合理。
- 经验上，酚、胺、醇、醛、酸、硫醇同时存在时，LLM 特别容易低估副反应与兼容性问题。
- 即使系统没报警，也要主动想一遍：下步条件是否真的允许裸官能团存在。

### 先验 10. 当继续下拆只剩低可信模板时，诚实的 advanced terminal 优于假深拆
- 当继续下拆只剩低可信模板时，可以接受 advanced terminal。
- 停止的理由必须是“再拆会更假”，而不是“暂时拆不动”。
- 若再往下拆只会进入不常见、难买、易分解、纯为模板而生的前体，可考虑停在更像真实 building block 的 advanced terminal。

### 先验 11. 长程 route_plan 是路线 thesis，不是一步候选
- 对复杂目标，先建立一个短 `route_plan` 能减少局部模板贪心，帮助后续每一步保持全局路线一致性。
- `route_plan` 应记录核心拆分、偏好的前体逻辑、需要保留的成熟骨架、路线范式、范式证据、战略风险和修订触发器；当证据改变时要短修订，而不是在 reasoning 里静默漂移。
- 不要把完整 plan 历史注入默认上下文；LLM 只需要读 `route_plan_brief`。

### 先验 11b. 复杂目标先比较路线范式
- 首个复杂目标节点不要直接承诺完整从头合成路线；先把路线当作可修订假设。
- 在 `route_plan` 初始化时比较 `late_fgi`、`scaffold_assembly`、`electronic_state_strategy` 和必要的 `hybrid` 路线范式。
- 如果 action-space 主要给出局部 FGI/EAS/模板菜单，但没有解释核心骨架来源，应把它视为战略风险或修订触发器。
- terminal review 若发现 advanced terminal 仍隐藏最难核心构建问题，应修订 `route_plan`，而不是只在局部 terminal reasoning 里接受。

### 先验 11c. 电子贫多取代吡啶的电子态策略提醒
- 高度缺电子、多取代吡啶核心不要默认当作可 late EAS/halogenation 的成熟核心。
- 先比较 late FGI 与 scaffold assembly/electronic-state strategy；若最终芳香态过度缺电子，考虑 pyridone/lactam、dihydropyridine 或其他非最终电子态中间体，再转化为最终氯代吡啶。
- 这不是硬规则；只有在拓扑、取代模式、电子效应和可执行前体支持时才采用。经验卡只负责提醒比较，不强制 pyridone 路线。

### 先验 12. advanced terminal 前先做 bounded mini-route 复审
- 非平凡 advanced terminal 不是“系统暂时拆不动”的同义词。
- 接受前应先反问：如果把该分子当小目标，是否能由更简单前体经 1 到 3 步机理明确、选择性可信的 mini-route 到达？若可能，应通过 `route_sketch(..., terminal_review=True)` 记录，并把第一真实事件走 `propose_action -> try_action -> commit`；若还有后续步骤，交给 strategy continuation 继续显式复审。
- 若有可信的氧化态回退、选择性保护/脱保护、后期卤化、SNAr、Halex 或其他明确选择性来源，应先把下一步转成 `propose_action -> try_action`；若没有，再诚实接受 advanced terminal。

## 补充经验

### 局部升高 `CS` 可能是在为后面降维
- FGI、保护态调整、偶联兼容化处理，有时会让单步 `CS` 暂时升高。
- 这不等于路线变差，关键是看后面 3 到 5 步是否因此获得更自然、更稳定、更可收敛的拆分。
- 不要只因为某一步分数上升就放弃合理的中继转换。

### “更可买”通常意味着“更像真实 medicinal chemistry building block”
- 当两个方案机理都成立时，优先选择更稳定、更多供应商可能常备、形式更标准的中间体。
- 经验上，常见芳基卤、硼酸/硼酸酯、简单杂芳卤、酸、酯、受保护胺、常见杂环酸/酯，通常比奇怪的高活性瞬态前体更像真实采购节点。
- 优先让前期中间体保持稳定、可存放、可纯化、可购买。

### 命名反应只是默认先验，不是免检通行证
- `Suzuki`、`Buchwald-Hartwig`、`SNAr`、`Heck`、还原胺化等都只是反应家族，不是自动正确答案。
- 简单羰基 + 胺的还原胺化往往很强，但杂底物、位阻大底物、多亲核位点体系要更谨慎。
- 真正决定可信度的是底物匹配、选择性、保护负担、手柄时序和文献可比性。

### 反应可信度分层是先验，不是排名
- 默认较高：`amide coupling`、`sulfonamide formation`、常规保护/脱保护、简单芳香卤化、苄位氧化/还原、底物匹配明确的 `Suzuki` / `Miyaura`、位点清楚且竞争少的常规酯化/酯水解。
- 需结合底物上调或下调：`Buchwald-Hartwig`、`SNAr`、`Ullmann`、`Chan-Lam`、`Heck`、还原胺化、`Mitsunobu`、分子内环化、杂环构建。
- 默认较低：稠环强行开裂、不自然重排、只在模板上成立的深拆、无明显逻辑支撑的跨大步骨架转换、把多个真实步骤硬压成一步的方案。
- 若电子效应、位阻、离去基和手柄位置都匹配，可以上调；若依赖苛刻条件、选择性脆弱、保护负担重或文献先例稀少，应下调。

## 高频怀疑信号

### 1. 环大小误判
- 五元环看成六元环，或把并环共享原子数算错，是高频大错。
- 对稠合、桥连、螺环体系，必须重新逐原子数环。

### 2. 把离去基团误当成骨架来源
- 某些反应前体“原子更多”是正常的，因为有离去基团、金属、配体或临时手柄。
- 但产物侧无故多出骨架原子则不正常。

### 3. 把保护态变化误当作骨架变化
- 保护/脱保护只是战术步骤，不应被误读为核心骨架断裂或新骨架生成。

### 4. 因为模板成功或 gate clear 就放松机理审查
- 系统没拦不代表化学一定合理。
- 尤其在杂环构建、跨大步骨架转换和复杂关环上，必须回到机理本身。

### 5. 因为模板命中就忽略底物现实
- 模板可能只说明“形式上可映射”，不说明这个底物组合真的好做。
- 位阻、电子效应、竞争位点和保护负担，常常比模板类别本身更重要。

### 6. 把活化杂芳环局部卤化当作前期预埋
- 对很多活化杂芳体系，这类卤化更像后期编辑步骤。
- 如果过早预埋，往往会引入不必要的兼容性负担。

### 7. 看到成熟杂环就继续深拆到奇怪模板
- 若深拆主要依赖环内 `Williamson`、`Chan-Lam`、`Paal-Knorr`、奇怪重排或缺少文献语境的环构建，应先停下来怀疑方向是否错了。

## 可买性与 terminal 经验

### 更适合作为 advanced terminal 的候选
- 常见高级中间体
- 常见药化 building block
- 稳定、可存放、官能团负担不过重的片段
- 再往下拆只会进入明显模板化或 speculative 前体的节点

### 不适合作为 terminal 的候选
- 只是“看起来已经差不多”
- 只是因为当前模板不好拆
- 需要依赖极不常见或明显不稳定的即时前体
- 含有早装高活性把手，实际并不利于采购或储存

## 当前阶段的使用建议
- `SKILL.md` 保持“可执行宪法化”，只放角色边界、硬规则、工作流和审计要求。
- `refs.md` 保持“技术参考”，放命令、数据结构、工具行为。
- `experience.md` 专门沉淀经验先验、常见坑、反应选择的语境化偏好。
- `experience_cards.md` 是运行时挂载层，把本文档中的经验压缩成可按 tag 检索的短提醒。

这样各层分工会比较清楚：
- `SKILL.md` 定义执行边界、必须检查什么以及 LLM 如何行动
- `experience.md` 提供多个可行方案间更像真实化学家的经验偏好
- `refs.md` 说明工具怎么用、字段怎么读、系统内部怎么工作
- `experience_cards.md/json` 在某一步短暂提醒 LLM 检查最相关的问题

## 运行时经验挂载原则
- 不要在每个分子节点全文注入 `experience.md`。
- 默认从 `experience_cards.json` 动态选择最多 4 张卡片；terminal、advanced-terminal review 和 custom topology validation 场景最多 5 张，也允许没有匹配卡片。
- 默认挂载不是“读满”，而是“保留最有用的检查项”。高风险 topology / atom-source 场景优先保留 topology、proof obligation、template、custom-action 和 atom-source 提醒；family interpretation 只作为可选支持。
- 专用卡通过结构化 `activation` 条件准入。普通 scaffold 文本或反应名可以帮助化学空间排序，但不能单独触发 topology gate/guardrail。
- 卡片必须短、可执行、可引用；普通上下文只挂载 `id`、`one_line` 和 `action_prompt`。
- 长程路线、路线范式和 terminal mini-route review 在运行时对应 `exp_global_route_plan_persistence`、`exp_route_plan_revision`、`exp_route_mode_triage_before_first_plan`、`exp_electron_poor_pyridine_electronic_state_strategy` 和 `exp_advanced_terminal_short_route_rescue` 等短卡片。
- commit/report 记录使用过的卡片 `id`，不要复制卡片全文。
