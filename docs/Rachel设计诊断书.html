01 · 现状快照

Rachel-v2 现在长什么样

从 index.html 引用的 index-DL9q63xt.js / index-Ddy2iZUO.css 反推：Vite 打包的 React 单页应用，路线树用 @xyflow/react（React Flow），分子结构渲染直接内嵌了 RDKit_minimal.js。整体是 Tailwind 默认值上加了三个自定义变量， 没有再往下建立完整的设计令牌层。

02 · 对照基准

AlphaFold Server 的设计语言从哪来

AlphaFold Server 是 Angular + Angular Material 构建的（页面里能看到大量 mat-mdc-* 类名）。它的「产品感」不是靠一次性视觉设计堆出来的， 而是直接继承了 Google Material Design 3 的整套体系：色彩、字体、形状、图标、动效全部是 平台级组件自带的，团队只需要往组件里填内容。

色彩系统

--dmat-blue-* 变量

不是几个孤立的色值，而是一整条 tonal 色阶（0/5/10/…/100），每一级还配一个 -auto-contrast 版本自动算前景色。背景在浅色 #fdfdfd 和深色 #0a0a0a 之间整体切换，不是补丁式的深色规则。

blue-10 blue-30 blue-40 blue-50 blue-70 blue-90 blue-97

字体 / 形状 / 图标

  • 字体 — Google Sans / Google Sans Display / Google Sans Mono，正文、标题、数据分别用不同字重的品牌字体，不是系统默认栈
  • 圆角 — 从 4px 一路到 28px，卡片 / 对话框 / Chip 用大圆角，输入控件保持适中，形成明确的「容器大圆、控件小圆」规则
  • 图标 — Material Symbols，可变字重的图标字体，全站图标粗细统一
  • 输入方式 — 序列 / 结构不是塞进一个大文本框，而是 mat-mdc-chip + autocomplete 组成的「可增删结构化单元」
ⓘ 这套体系不是可以直接抄的 —— Google Sans 是 Google 内部字体，HCT 自动对比算法是 Material 3 的私有工具链。 下面的建议会取「同样的效果」而不是「同样的实现」：分层色阶、明确的圆角规则、结构化输入，这三件事在 Tailwind 里半天就能搭起来，不需要迁移到 Angular Material。

04 · 改造建议

按性价比排序，不是按重要性排序

分三档。P0 都是「一两天能改完、视觉观感立刻不一样」的事；P1 需要新写一点组件； P2 是值得排进季度计划但不急的投入。技术栈全程不动：还是 React + Tailwind + React Flow + RDKit.js。

P0 · 现在就能做 低成本，视觉感知最强

01把 3 个色变量扩成一整套令牌

在现有 --color-primary / --color-deep / --color-bg 基础上补出 --surface / --border / --text-dim / --success / --warning / --danger 这一层语义令牌，灰阶延续现在 slate 系带一点蓝的偏色，不用引入 Material 那套自动对比算法。

02把深色模式从「1 条规则」接成「1 套令牌」

令牌层做好之后，加一个 @media (prefers-color-scheme: dark) 覆盖同一批变量即可。这是目前投入产出比最高的一步——现在的深色模式本质上是没做的。

03统一圆角：容器大圆、控件小圆

输入框 / 按钮保持现在的 6–8px，卡片、任务详情面板、弹窗升级到 12–16px。不是所有地方都放大圆角，是分两级，制造出主次层次。

04示例从纯文字换成可点结构卡片

提交页的「阿司匹林」「扑热息痛」用 RDKit_minimal.js（已经全局加载了）现场渲染成 2D 结构缩略图，点击直接填充，而不是纯文字。这是最贴近 AlphaFold「结构化实体输入」体验、且成本最低的一条，因为渲染能力已经在跑了，只是没接到示例上。

05空状态 / 加载态组件化

「还没有任务」配一个小图标 + 「去提交」按钮的组合卡片；「加载中」换成灰色骨架块（哪怕只是任务列表的 3 行占位矩形）。改动量很小，但立刻减少「内部工具感」。

P1 · 值得投入 需要新写组件，一到两周量级

06阶段状态机做成横向 Stepper

初始化 → 路线规划 → 策略调整 → 收尾 → 导出 → 完成，这 6 步已经是现成的枚举，包一层横向进度条组件（当前高亮、已完成打勾），「实时 / 轮询降级 / 已结束」这类连接状态改成一个带颜色的状态点，替换掉纯文字。

07路线树节点嵌结构缩略图

React Flow 的「分子节点」目前是文本方框，「边信息」面板才显示结构。把 RDKit 渲染的 2D 结构图直接放进节点卡片本身，让路线树本身就是可读的化学图，而不是要点开弹窗才看得到分子长什么样。

08结果页从文件列表变仪表盘

报告 Tab 现在是「报告文本 / 合成树 / 起始原料 / 消息日志」一串可下载文件，加「合成报告」按钮新窗口打开。把步数、耗时、产物指标做成页内的大数字卡片（呼应 AlphaFold 结果页的分数卡片），下载入口保留但降级为次要按钮，不用跳出应用看结果。

09引入一套统一图标库

查看 / 取消 / 删除 / 刷新 / 导出这些操作现在基本是纯文字按钮。换成 Lucide 或 Heroicons 统一走一遍，不需要做到 Material Symbols 那种可变字重图标字体的程度，但至少视觉粗细要统一。

P2 · 排进长线 季度级投入，非阻塞项

10引入一款品牌字体

现在是纯系统默认字体栈，完全没有识别度。不需要也拿不到 Google Sans，可以选一款开源无衬线体（比如 IBM Plex Sans 或 Manrope）自托管或走 Google Fonts，建立「这是 Rachel」而不是「随便一个后台」的识别度。

11评估无样式组件库地基

AlphaFold 的一致感很大程度来自 Angular Material 提供的成熟组件。如果 Rachel 前端还处在早期，值得评估 Radix UI / shadcn 这类无样式组件库，把现在分散的自定义弹窗 / 表单统一到一套基础组件上，减少长期维护中的视觉漂移。

12管理后台跟主流程视觉打通

「供应商管理」目前是纯功能表单风格，跟面向科学家的任务流程是两套视觉语言，等 P0/P1 令牌层稳定之后一起收编。

05 · 边界

不建议做的事

照抄整套 Material 体系的投入产出比对一个小团队不划算，以下三件事建议明确排除在改造范围外。

×

不迁移到 Angular / Angular Material。AlphaFold 的「科学感」更多来自令牌一致性和结构化输入，不是框架本身。React + Tailwind + React Flow + RDKit.js 完全够撑起 P0/P1 的所有改动。

×

不复刻 HCT 自动对比色算法。那是 Material 3 内部工具链的产物，前面提到的「5–7 级色阶 + 深色模式媒体查询」已经能达到同等的视觉效果，手写一遍自动对比算法不值得。

×

不为了「像 AlphaFold」改登录方式。邮箱验证码 + 密码的认证流程本身没有问题，跟视觉改造无关，不要顺手一起改掉。
