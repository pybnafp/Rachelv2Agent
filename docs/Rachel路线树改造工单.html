把前两份诊断落成可以直接派工的 15 个改动

这份是给实际动手改代码的人看的，不是给决策看的——前因、取舍、参考案例在前两份诊断书里，这里只留「改什么、 在哪改、改成什么样、怎么算做完」。三个 Track 按「现在就能做」→「先确认一个字段是否已经有」→「值得立项但要先做原型」排列。

2026-08-19 前置阅读：Rachel 设计诊断书 / Rachel 路线树诊断书 执行者：拿到 Rachel-v2 前端仓库权限的开发者
★ 写工单之前又挖了一层，发现一件事值得先说：写路线树诊断书时我以为「试剂/条件/证据来源」这些字段在后端完全不存在， 需要新增数据模型。结果去读了 Rachel 的 Python Skill 源码（Rachel/main/retro_tree.py）才发现这些字段其实已经在了： ReactionNode.reagents（试剂 SMILES 列表）、template_evidence（模板 id / 名称 / 知识引用， 本质就是「listed vs custom」的判据）、llm_decision（选择理由 / 置信度 high-medium-low / 风险评估）。 问题很可能不是「没数据」，是「web 平台的 API 层没把这些字段转发给前端，或者前端拿到了但没读」—— 这把 Track 2 里好几张原本以为要「先立项做数据模型」的工单，降级成了「先打一次接口确认」。见 T10–T12。
Track 1 · 纯前端，现在就能做

不依赖任何后端确认的 9 个改动

T1

箭头方向反转

改动量：约 1 行
定位
路线树画布组件里构造 edges 的那一段，边对象带 markerEnd:{`{type:ArrowClosed}`}
现状
边的 source 是较浅（更接近目标）一端，target 是较深（更接近原料）一端；markerEnd 把箭头画在 target 端，视觉上箭头从目标指向原料
改法
把 markerEnd:{`{type:ArrowClosed}`} 换成 markerStart:{`{type:ArrowClosed}`}；不改布局算法、不反转 source/target 字段本身
验收
  • 任取一条边，箭头指向蓝色（target）方向，不是背离
  • 找一条有汇聚步骤（多个前体合并成一个中间体）的真实路线，确认分支汇聚处箭头依然清楚不重叠
T2

反应式渲染成图，不再是原始文本

改动量：小，复用已有渲染管线
定位
侧边详情抽屉里 data-testid="drawer-rxn-smiles" 那个 <code> 块，现在直接输出 reaction_smiles 原始字符串
改法
找到画分子结构图用的那个 RDKit 封装组件（分子卡片和抽屉里画 smiles 的那个），确认它是否也能接反应 SMILES（"A.B>>C" 格式，RDKit.js 原生支持 get_rxn 系渲染）；能的话直接复用同一渲染函数把 reaction_smiles 画成反应物→箭头→产物的图式，替换掉抽屉里的等宽文本块（原始文本可以保留在图下面一行，供复制）
验收
  • 点开任意反应节点，抽屉里看到的是渲染出来的反应图式，不是一行字符串
  • 反应式解析失败时有兜底（显示原始文本 + 提示，不能白屏）
T3

反应节点从药丸升级成卡片

改动量：小-中
定位
data-testid="rxn-pill-{`{id}`}" 组件，现在是 rounded-full border-amber-500 bg-amber-100 的药丸，文本超 18 字符截断加省略号
改法
改成跟分子卡片同量级的卡片（不用做成一样大，但要放得下完整反应名）；文本来源建议用后端的 reaction_type 字段（人类可读的反应家族名），不要再截断；如果 T10 确认 reagents 字段已透传，直接把试剂小结构图一并画进这张卡片
验收
找一个反应家族名较长（>18 字符）的真实节点，全名可见，不用 hover 也能读
T4

去掉/重定向边的空信息面板

改动量：小
定位
画布的 onEdgeClick 处理函数，现在打开的抽屉只显示 source / target / type: smoothstep
改法
两选一：① 直接去掉边的 onClick；② 点边时改成打开这条边相邻反应节点的详情（等价于点了那个反应卡片）
验收
点连线不再弹出「type: smoothstep」这种无意义信息
T5

画布常驻图例

改动量：小
改法
画布上方或角落加一行常驻小图例：● 目标（蓝）　● 中间体（灰）　● 可购买原料（绿）；如果 T11 做了 listed/custom 区分，一并加进同一行图例
验收
不点任何节点，新用户也能看懂三种颜色分别是什么
T6

cs_score 加说明

改动量：小，文案已确认
依据
后端 chem_tools/cs_score.py：CS = Complicated Score（分子复杂度评分），范围 1.0–10.0，越高越复杂；classification 三档：trivial / moderate / complex，trivial 会被自动判定为 is_terminal
改法
分子卡片 / 抽屉里的 cs_score 数字加 hover tooltip 或图例条，文案可以直接用：「CS 复杂度评分（1–10，越高越复杂）」；classification 三档同时给出中文短标签（简单 / 中等 / 复杂）
T7

删除小地图

改动量：删一行
定位
画布组件里挂载 <MiniMap pannable zoomable /> 的那一行（data-testid="rf__minimap"），没有传 position/width/height，吃 React Flow 默认值 200×150px 右下角
改法
直接删掉这行挂载，保留 <Controls/>（缩放/适应视图）
验收
画布右下角不再有缩略图色块；对一棵真实的大路线树（几十个节点）确认没有任何东西被之前小地图的位置挡住
T8

锁定按钮改接画布冻结，不再切换「节点可拖动」

改动量：中
定位
data-testid="rf__controls" 里那个锁形按钮，是 React Flow Controls 组件自带的「交互开关」，默认逻辑是 setState({`{nodesDraggable:!h, nodesConnectable:!h, elementsSelectable:!h}`})
现状
画布组件本身已经把 nodesDraggable 写死成 false，节点也没有连线/多选场景，所以这个按钮点击后切换的三个状态对视觉没有任何影响，等同于「点了没反应」
改法
把 <Controls showInteractive={`{false}`}/> 关掉默认的锁按钮，自己加一个 <ControlButton/>（React Flow 有导出这个子组件），用本地 state 控制，锁定时把 <ReactFlow/> 的 panOnDrag / zoomOnScroll / zoomOnPinch / zoomOnDoubleClick 一起设为 false，图标复用现成的锁形
验收
点击锁定后，鼠标滚轮 / 拖拽 / 双击都不能再改变画布的平移缩放位置；再点一次能解锁
T9

classification 从抽屉搬到卡片

改动量：小
纠正
上一份诊断书猜测这个字段「大概率经常是空值」——核实后是错的：classification 来自后端真实计算（trivial / moderate / complex 三档），不是空占位
改法
在分子卡片上加一个小标签展示这三档（复用 T6 的中文短标签），不用非得点进抽屉才能看到
Track 2 · 先确认字段是否已经透传

大概率不需要新数据模型的 3 个改动

下面三张工单都依赖同一个前置动作：登录后打一次真实的 GET /api/jobs/{`{id}`}，看返回的 reaction 节点 JSON 里有没有 reagents / template_evidence / llm_decision 这几个 key。

后端字段（retro_tree.py 里已确认存在）形态如果 API 里有如果 API 里没有
reagentsSMILES 字符串列表前端加渲染逻辑即可（T10）去查 web 平台自己的 API/BFF 层（不在这份 skill 代码包里）的序列化逻辑，是不是把这个字段过滤掉了
template_evidence对象：template_id / template_name / reaction_category / knowledge_refs存在即 listed，缺省即 custom（T11）同上，先查 API 层
llm_decision对象：selection_reasoning / confidence(high/medium/low) / risk_assessment加进抽屉新区块（T12）同上，先查 API 层
T10

试剂画成图，贴在反应箭头上方

改动量：小（若字段已透传）
做法
reagents 是 SMILES 列表，不是自由文本——用跟 T2 一样的 RDKit 渲染管线，把每个试剂画成一个小结构图标，贴在反应卡片/反应图式的箭头上方，就是论文合成图式那种画法，不用额外设计新的展示形式
验收
找一个 reagents 非空的真实反应节点，能看到试剂结构图标，不是空的
T11

listed / custom 二级颜色区分

改动量：小（若字段已透传）
判据
template_evidence 字段存在（即有 template_id/template_name）→ listed，有已知模板依据；不存在 → custom，LLM 现推的新假设
做法
反应卡片加一个二级视觉标记（图标或细边框颜色，不要跟三色角色系统的主色冲突），listed 用偏「已验证」的颜色、custom 用偏「待观察」的颜色；knowledge_refs（知识引用列表）如果有值，在抽屉里列出来，类似参考文献链接
验收
能在画布上不点开任何节点，直接看出「这一步有模板依据」还是「这一步是本次探索现推出来的」
T12

抽屉里加「为什么这么设计」区块

改动量：小（若字段已透传）
做法
反应节点抽屉新增一个区块，展示 llm_decision.selection_reasoning（选择理由）、confidence（转成中文：高/中/低）、risk_assessment（风险评估）；rejected_alternatives 如果有值，可以做成一个可展开的「其他考虑过的方案」列表
验收
点开一个反应节点，能读到当时为什么选这一步、有多大把握、有什么风险，不需要再去问后端团队
Track 3 · 先做原型再立项

工程量较大的 3 项

T13

主线视图 / 完整探索图，双视图切换

改动量：大
做法
新增一个默认视图：只画从底物到目标分子的那条被 commit/accept 的主线，按 depth 分层的线性/瀑布布局，用普通 flex/grid 实现，不需要 React Flow；现有的画布组件保留，作为「查看完整探索过程」的第二个视图（tab 切换），不要删掉
验收
两个视图能来回切换，数据一致；主线视图下不需要小地图/锁定这类画布控件，因为它本来就不是无限画布
T14

结构图放大查看器

改动量：中，先确认渲染模式
前置确认
RDKit 封装组件当前输出的是 SVG 还是位图（canvas/PNG）——如果是 SVG，缩放到任意倍数都不会糊，放大查看器只需要一个可滚动/缩放的容器；如果是位图，放大查看器需要在用户改变缩放级别时用新的 width/height 重新调用 RDKit 生成，不能把小图直接拉伸
做法
点击任意分子/反应结构图 → 弹出一个支持滚轮缩放、拖拽平移的大图查看器
T15

候选路线对比页

改动量：大，仅在「多候选路线」需求成立时做
触发条件
只有当产品需要给用户展示多条候选路线供选择时才做，如果目前每个 job 本来就只产出一条最终路线，这项不需要
做法
参考 Reaxys 的 Routes Overview：候选路线列表页，每条路线一行，配一张路线复杂度缩略图 + 所需起始原料清单，用户先在这一层选路线，再进入 T13 的详细视图
依据来源：Rachel-v2 web 平台的编译前端产物（index-*.js/css，静态分析非截图走查）+ Rachel Python Skill 源码 Rachel-2.11-20260816 里的 Rachel/main/retro_tree.py、 Rachel/chem_tools/cs_score.py。两者是否共用同一套字段命名/序列化逻辑未做真机验证（job API 需要登录态）， Track 2 的判断方法已写清楚，交给有权限的开发者一次接口调用即可确认。
